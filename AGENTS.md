# AGENTS.md

## Обзор проекта

`medical-questionnaire` — задуманная программа для медицинского опроса пациентов. Так назначение проекта описано в `README.md`. В текущем состоянии репозиторий содержит только минимальный каркас на Python, а не реализованную систему опроса.

- Версия проекта: `0.1.0`.
- Требуемая версия Python: `>=3.13`; файл `.python-version` закрепляет `3.13`.
- Менеджер окружения и lock-файла: `uv` (`uv.lock`).
- Внешние зависимости отсутствуют: в `pyproject.toml` указан пустой список `dependencies`.
- Лицензия: MIT (`LICENSE`).
- Основная документация и этот файл написаны на русском языке.

Не следует считать каталог `backend` веб-сервером: фреймворк, API, база данных, модели предметной области и обработчики опросов пока не реализованы. Фронтенд и отдельные исполняемые компоненты также отсутствуют.

## Конфигурация, сборка и запуск

Главный конфигурационный файл — `pyproject.toml`. Он задаёт метаданные проекта, версию Python и зависимости. В текущем файле **нет** секций `[build-system]` и `[project.scripts]`:

- команда `medical-questionnaire` после синхронизации окружения не объявляется;
- настроенного способа собрать wheel или sdist нет;
- корневой проект представлен в `uv.lock` как `virtual`.

Проверка и синхронизация окружения из корня репозитория:

```bash
uv lock --check
uv sync --locked
```

`PYTHONPATH=backend/src` необходим для такого прямого импорта, поскольку текущая конфигурация не устанавливает корневой проект как пакет. Не нужно предполагать наличие консольной команды или точки входа, пока они явно не добавлены в `pyproject.toml`.

При добавлении зависимостей следует обновлять и `pyproject.toml`, и `uv.lock` средствами `uv`, чтобы окружение оставалось воспроизводимым.

## Стиль кода

Явной конфигурации форматтера, линтера или проверки типов в `pyproject.toml` нет. Наличие `.ruff_cache/` само по себе не задаёт правила Ruff.

По единственному существующему модулю можно сохранять уже использованные простые соглашения:

- отступы в четыре пробела;
- двойные кавычки для строк;
- аннотация возвращаемого типа у функции;
- импортируемый пакет в snake_case, распределённое имя проекта в kebab-case.

Этого кода недостаточно, чтобы выводить более строгие проектные правила. Не следует ссылаться на несуществующие настройки Black, Ruff, mypy или других инструментов.

## Тестирование

В репозитории нет тестов, каталога `tests`, тестовых зависимостей, конфигурации pytest или другого тестового раннера. Поэтому стандартная команда запуска тестов пока не определена; не стоит считать `pytest` установленным или настроенным.

Для текущего кода доступна ручная проверка запуска, приведённая выше. Дополнительно можно проверить согласованность lock-файла командой `uv lock --check`.

Если тесты будут добавлены, вместе с ними нужно явно определить тестовые зависимости и команду запуска, а затем обновить этот документ.

## Развёртывание и CI

Процессы развёртывания и непрерывной интеграции не настроены: в репозитории нет Dockerfile, workflow CI/CD, сценариев развёртывания или описания production-окружения. Также отсутствуют конфигурация сервера приложений и упаковки. Не следует выдумывать команды деплоя или целевую платформу на основании названия каталога `backend`.

## Безопасность и локальные данные

Текущий код не читает файлы, не принимает сетевые запросы, не работает с базой данных и не обрабатывает данные пациентов. Механизмы аутентификации, авторизации, шифрования или хранения медицинских данных в проекте пока не реализованы.

`.gitignore` исключает `.env`, `.envrc`, виртуальные окружения, локальные настройки IDE, базы SQLite и типичные артефакты сборки и тестирования. Секреты и локальные данные не должны добавляться в отслеживаемые файлы. При появлении реальной обработки персональных или медицинских данных соответствующие требования необходимо будет описать отдельно на основании фактической реализации.

## Область действия

Этот AGENTS.md применяется ко всему репозиторию.

Для отдельных частей проекта используются дополнительные инструкции:
- `/frontend/AGENTS.md` — правила для React-приложения
- `/backend/AGENTS.md` — правила для API и работы с базой данных

Если инструкции конфликтуют, используй более близкий к изменяемому файлу AGENTS.md.
Явная инструкция пользователя в чате имеет приоритет над правилами из файла.
